# Privacy and data

This document describes what the bot stores and how to get it removed. It is a
technical description, not legal advice. Communities should adapt it to their local
rules and publish a member-facing privacy notice.

## Short version

- **No chat message bodies are stored.**
- The bot stores a small profile, a GitHub link, a score, badges and an activity
  ledger keyed by GitHub contribution IDs.
- AI prompts are sent only to the Ollama server you configure. There is no paid AI
  provider and no analytics SDK.
- Members can inspect, opt out of, and delete their data from chat.

## What is stored

| Data | Table | Why | Retention |
| --- | --- | --- | --- |
| Platform, user ID, display name | `members` | Reply to the right person, show the leaderboard | Until deletion |
| Language preference | `members.locale` | Reply in the chosen language | Until changed/deleted |
| Opt-out flag | `members.opted_out` | Respect consent | Until changed/deleted |
| GitHub username | `links`, `member_links` | Score contributions and show the leaderboard | Until unlink/deletion |
| Points, badges, current challenge | `links` | Gamification and continuity | Until unlink/deletion |
| Activity event keys, type, points, title, URL, timestamp | `activity_events` | Award each contribution once; prevent double counting | `RETENTION_DAYS` (default 365) |
| Selected repository | `settings` | Know what to poll | Until changed |
| Telegram update offset | `settings` | Resume polling without replaying old messages | Until changed |
| Operational logs | stdout / journald | Debugging and security | Your logging retention |

The bot does **not** store:

- message text, attachments, reactions or voice;
- email addresses, phone numbers or passwords;
- GitHub tokens in the database (they stay in environment variables);
- AI conversation history on disk (it is in memory only, bounded, and cleared on
  restart);
- IP addresses in the application database.

The HTTP server may see an IP address in the reverse proxy access log; that log is
outside the bot.

## AI processing

`ask`, DM chat, `challenge` and `sentiment` send a prompt to the Ollama HTTP API at
`OLLAMA_BASE_URL`.

- If Ollama runs on the same host, prompt content stays on that host.
- If you point `OLLAMA_BASE_URL` at a remote/cloud Ollama service, that operator can
  see the prompt. Disclose this to members.
- The bot sends only the question/text being processed, the activity summary for a
  challenge, and (for `ask`) a short in-memory conversation history. It does not send
  the database, tokens, member list or other channels.
- Ollama's own logs and model behavior are outside this project's control.
- AI output is not stored, except that a generated challenge is saved on the link so
  it can be shown again. If you do not want challenges stored, clear
  `links.current_challenge` or change the code.

## Consent and control

### Inspect

```text
!privacy
```

Shows the linked GitHub username, points and language. It does not expose internal
IDs.

### Opt out

```text
!privacy optout
```

The bot stops tracking and replying to community commands. It still answers privacy
and opt-in commands so the member can return. Opting out does not delete existing
data automatically; use deletion for that.

### Opt in

```text
!privacy optin
```

### Delete

```text
!privacy delete confirm
```

Only in a **direct message**. This removes:

- the `members` row;
- the `member_links` mapping;
- if this was the last chat identity linked to that GitHub account, the `links` row,
  activity ledger and challenge.

If the same GitHub account is linked from another platform, the shared link and score
remain for that other identity. This is intentional: deleting one chat profile should
not erase another person's shared score. To remove the shared GitHub identity, unlink
all chat identities or ask an admin.

Deletion is immediate in the live database. Backups may contain older copies until
they expire; document your backup retention.

### Admin unlink

```text
!unlink discord:123456789012345678
```

Removes the mapping. If it was the last mapping, the score/ledger for that GitHub
account is removed. This is an administrative action and should follow your community
policy.

## Legal bases and member notice (example)

Depending on your jurisdiction, you may rely on legitimate interests (operating the
community), consent (optional AI features) or contract. A short notice you can adapt:

> This community uses a self-hosted bot to celebrate GitHub contributions. It stores
> your chat platform ID, display name, language choice, GitHub username, points and
> badges. It does not store message contents. AI replies are generated by a local
> Ollama server. You can inspect, opt out of, or delete your data with `!privacy`.
> Contact the maintainers for questions.

## Security

- `.env` contains secrets; keep it `600` and out of Git.
- The bridge is disabled unless a shared secret is set. Use TLS in front of it.
- GitHub webhook signatures are verified.
- Admin actions are allowlisted per platform.
- Logs redact common token formats, but do not log secrets deliberately.
- Back up the database encrypted if it contains personal data.

See [SECURITY.md](../SECURITY.md) for vulnerability reporting.

## Children

The bot is intended for open-source community collaboration and is not directed at
children. Communities with younger members should review their own consent and
safeguarding requirements.

## Changes

Material changes to what is stored should be recorded in `CHANGELOG.md` and, where
appropriate, announced in the community. The schema migration history is in
`src/github_community_bot/storage.py`.
